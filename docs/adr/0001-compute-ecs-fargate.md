# 0001. 컴퓨트로 ECS Fargate 를 선택한다

- 상태: 승인
- 날짜: 2026-08-24

## 배경

LLM Gateway 는 다음 특성을 갖는다.

- **응답이 길다.** LLM 생성은 수 초에서 수십 초가 걸린다. 스트리밍이면 연결이 그
  시간만큼 유지된다.
- **SSE 스트리밍이 필수다.** OpenAI 호환을 목표로 하므로 `stream: true` 를
  지원해야 한다.
- **트래픽이 불규칙하다.** 조직 내부 도구라 업무 시간에 몰리고 야간에는 거의 없다.
- **상태를 갖지 않는다.** 모든 상태는 DynamoDB 에 있다.

조직의 기본 컴퓨트 선택 순서는 Lambda → Fargate → App Runner → EKS → EC2 이며,
상위 순위를 탈락시킬 때 사유를 남기도록 되어 있다. 또한 사용자가 ECS 구성을
명시적으로 요구했다.

## 결정

**ECS Fargate** 를 쓴다. 컨테이너 이미지는 ECR 에 두고, ALB 를 앞단에 둔다.

- 태스크: 0.5 vCPU / 1 GiB (파라미터로 조정)
- 상시 태스크 수: dev 1개, prod 2개 이상 권장
- 오토스케일링: CPU 60% 목표 추적, 상한 4
- 배포: 롤링 업데이트 + 서킷 브레이커 + 자동 롤백

## 검토한 대안

### 1순위: Lambda (컨테이너 이미지) — 탈락

가장 먼저 검토했고, 다음 이유로 탈락시켰다.

- **API Gateway 통합 타임아웃 30초.** HTTP API 와 REST API 모두 통합 타임아웃이
  최대 30초다. LLM 응답이 30초를 넘는 일이 흔해 정상 요청이 504 로 끊긴다.
- **스트리밍 경로가 제약된다.** Lambda 응답 스트리밍은 함수 URL 이나 ALB 를 통해서만
  가능하고 API Gateway 는 지원하지 않는다. 함수 URL 을 쓰면 API Gateway 가 주는
  스로틀링·WAF 연동을 잃고, ALB 를 쓰면 Fargate 대비 이점이 사라진다.
- **동시성 모델이 맞지 않는다.** Lambda 는 요청 1건당 실행 환경 1개를 점유한다. 이
  워크로드는 대기 시간이 대부분(Bedrock 응답 대기)이라 한 프로세스가 수십 개
  요청을 동시에 처리하는 편이 효율적이다. Fargate 태스크 하나가 스레드풀로 수십
  건을 동시에 처리한다.
- **사용자가 ECS 를 명시적으로 요구했다.**

Lambda 가 유리했을 조건: 응답이 짧고(수 초), 스트리밍이 필요 없고, 트래픽이
간헐적이라 유휴 비용이 지배적인 경우.

### 3순위: App Runner — 탈락

- ALB 를 직접 제어할 수 없어 접근 CIDR 을 보안 그룹으로 좁히는 방식을 쓸 수 없다.
  이 프로젝트는 인터넷 노출 범위를 CIDR 로 제한하는 것이 요구사항이다.
- 사용자가 ECS 를 요구했다.

### 4순위: EKS on Fargate — 탈락

- Kubernetes 생태계 요구가 없다. 컨트롤 플레인 비용(월 약 $73)과 운영 부담이
  얻는 것보다 크다.

### 5순위: EC2 — 탈락

- OS 패치와 오토스케일링 그룹 관리가 추가된다. 서버 관리가 필요 없는 선택이
  가능한 상황에서 고를 이유가 없다.

## 결과

**얻는 것**

- 30초 타임아웃 제약이 없다. 긴 스트리밍 응답을 그대로 중계한다.
- 커넥션 재사용과 인메모리 캐시가 유지되어 요청당 DynamoDB 조회가 줄어든다.
  콜드 스타트가 없다.
- 정적 대시보드를 같은 컨테이너에서 서빙해 CloudFront·S3 구성이 필요 없다.
- 표준 컨테이너라 로컬에서 `docker run` 으로 동일하게 재현된다.

**잃는 것**

- **유휴 비용이 발생한다.** 요청이 없어도 태스크가 돌아 월 약 $18 가 든다. ALB
  까지 합치면 약 $35 다. Lambda 면 유휴 시 $0 였다.
- **스케일 반응이 느리다.** 태스크 기동에 30초 이상 걸린다. 급격한 스파이크는
  오토스케일링이 따라가기 전에 지연으로 나타난다.
- 태스크 수를 직접 관리해야 한다.

**새로 생기는 운영 부담**

- 기반 이미지 취약점 패치를 위해 주기적으로 재빌드·재배포해야 한다. ECR 스캔
  결과를 확인하는 절차가 필요하다.
- 배포 시 태스크 교체를 지켜봐야 한다. 서킷 브레이커로 자동 롤백을 걸어 완화했다.

**비용 영향**

기본 구성(1 태스크) 월 약 $35, prod 구성(2 태스크) 월 약 $53. 자세한 내역은
README 의 비용 절에 있다.

## 재검토 조건

다음 중 하나가 성립하면 이 결정을 다시 본다.

- Bedrock 응답이 대부분 10초 안에 끝나고 스트리밍 요구가 사라진 경우
- API Gateway 통합 타임아웃 제약이 완화된 경우
- 트래픽이 하루 수십 건 수준으로 줄어 유휴 비용이 전체의 대부분을 차지하는 경우
